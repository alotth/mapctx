  - summary: Extend Project sync to additional optional fields such as `priority` and `workload`.
  - description: |
      ## Product Context
      Once dates work, teams want more planning metadata to stay aligned between local tasks and GitHub Projects.

      ## User Story
      As an operator, I want optional field mappings for `priority` and `workload` so Project views reflect the same planning metadata as local files.

      ## Expected Outcome
      Additional field sync remains optional, config-driven, and backward compatible for users who only map status and dates.

      ## Acceptance
      - [ ] Mapping rules for `priority` and `workload` are documented.
      - [ ] Additional Project field sync is implemented behind optional config.

      ## Open Decisions for Execution
      - [open] Should `workload` map to a single-select field, a numeric field, or support both with explicit config?

      ## Constraints
      Keep mapping optional and avoid breaking users that only configure status and date fields.

      ## Steps
      - [ ] Define supported mapping shapes for `priority`.
      - [ ] Define supported mapping shapes for `workload`.
      - [ ] Implement and document the optional config model.
