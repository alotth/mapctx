# T-051

  - role: backend
  - impact: high
  - estimatedEffort: 1w
  - prerequisites: [T-058]
  - blocking: [T-053, T-055, T-061]
  - filesAffected: [packages/planner]
  - testsRequired: [DAG tests, path collision tests, wave determinism tests, non-runnable-status exclusion tests]
  - summary: Replace dependency-only waves with dependency and resource-aware scheduling, advisory claims, and post-hoc violation detection.
  - description: |
      ## Product Context
      Safe multi-agent parallelism depends on domains and predicted paths, not dependencies alone.
      Those predictions are made before the code they describe exists, so they are wrong in both
      directions before real usage calibrates them.

      ## Expected Outcome
      Planner emits deterministic waves that reduce, but do not guarantee, conflicting writes —
      claims are advisory, not a correctness guarantee — and explains why tasks cannot overlap.
      Realized collisions and lost parallelism are both detected after the fact via `ClaimViolation`,
      never promised away at planning time.

      ## Acceptance
      - [x] Model domain/path read-write claims with confidence and provenance.
      - [x] Respect DAG, resource collisions, executor capacity, and workflow gates.
      - [x] Exclude paused/review epics and non-runnable statuses from next-work recommendations.
      - [x] Recommend executable leaf tasks instead of container epics.
      - [x] Planner explains, per serialized pair, which claim caused the split — the explanation is
            a first-class output, not a log line, because T-061's `overbroad` detection consumes it.
      - [x] Waves are deterministic: the same board and claim set produce byte-identical wave
            assignment across runs.
      - [x] Resource claims are documented and treated as advisory scheduling hints, not correctness
            guarantees; the worktree merge remains the real conflict backstop. Planner docs and
            output never phrase wave scheduling as "conflict-free," only as "collision-aware."

      ## Decisions Taken
      - [2026-08-15] Claims are advisory; worktree merge is the real backstop. Planner promise
        changes from "avoid conflicts" to "reduce likely conflicts and detect the rest via
        `ClaimViolation`." See ADR 0003 §Resource claims are advisory.
      - [2026-08-15] `ClaimViolation` is a single entity with `kind: collision | overbroad`, derived
        at wave-completion time from receipt `changedFiles` diffing, not a real-time check.
      - [2026-08-15] No ML or automatic calibration in v1; the `ClaimViolation` stream is shaped for
        future calibration but tuned manually for now.
      - [2026-08-16] Split: `ClaimViolation` detection moved to T-061. It diffs `changedFiles` across
        a completed wave's `RunReceipt`s, and T-058 proved receipts have no durable home until T-060
        lands. Keeping detection here would have blocked the whole planner behind store work it does
        not otherwise need. T-051 stays schedulable now; T-061 depends on both T-051 and T-060.
      - [2026-08-17] Planner delivered as `@mapctx/planner` library with `planExecution`/`planWaves`
        aliases. It consumes protocol `ResourceClaim`, `DependencyEdge`, and `WorkflowGate` types;
        legacy `domains`/`touch` hints can be deterministically projected into advisory claims.
      - [2026-08-17] Waves dispatch only executable leaf `backlog`/`ready` work. `doing`/`in-progress`,
        `review`, `paused`, and `blocked` remain graph context but never consume executor capacity or
        appear in next-work recommendations. Named dependency/gate blockers remain first-class output.
      - [2026-08-17] CLI wiring is intentionally deferred until T-060's `mapctx-cli.ts` work lands;
        this ticket's programmatic planner API and tests are the integration seam.

      ## Steps
      - [x] Migrate `domains`/`touch` into ResourceClaim views.
      - [x] Implement collision-aware wave planner and per-pair serialization explanations.
      - [x] Fix the known planner defect: `paused`/`review` tasks and container epics currently count
            as runnable next work.
