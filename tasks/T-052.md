  - summary: Define executor-neutral dispatch, event, and receipt lifecycle.
  - description: |
      ## Product Context
      Traycer, Orca, and Paperclip expose different runtime models; core must not depend on any one.

      ## Expected Outcome
      One versioned contract carries bounded context out and normalized evidence back.

      ## Acceptance
      - [x] `DispatchEnvelope`, `RunEvent`, and `RunReceipt` require `schemaVersion`; an incompatible version is rejected (`schema-version.ts`, already tested in `contract.test.ts` — inherited from T-048, still true after this task's additive changes).
      - [x] `Dispatch.status` has a documented, tested transition table (`DISPATCH_TRANSITIONS` in `state-machines.ts`, same pattern as `PLANNING_TRANSITIONS`/`EXECUTION_TRANSITIONS`); every terminal state (`completed`, `failed`, `cancelled`, `expired`) has zero outgoing transitions, so a retry is always a new attempt, never a resurrection of an old one.
      - [x] `evaluateRunReceipt(history, receipt)` in `attempt-lifecycle.ts` is a pure function that accepts a receipt for the current attempt and rejects `stale-attempt` (receipt for an attempt older than the latest dispatched one — the retry race this task exists to solve), `duplicate-receipt` (attempt already has an accepted receipt), `unknown-attempt`, and `dispatch-mismatch`. No storage; `recordAttempt`/`recordAcceptedReceipt` are pure reducers T-058 will call against a real store.
      - [x] `DispatchEnvelope.executor.capabilities`, `context.hash`, `workflowEvidence`, `RunReceipt.changedFiles`, `RunReceipt.usageEvents`, and `RunReceipt.evidence` are all present and fixture-covered (inherited from T-048).
      - [x] `RunReceipt.failure` (`FailureDetail | null`) is required exactly when `outcome === "failed"` and forbidden otherwise, enforced by a `superRefine` and tested against both violations.

      ## Steps
      - [x] Implement `Dispatch.status` transition table (`DISPATCH_TRANSITIONS`) following the `PLANNING_TRANSITIONS`/`EXECUTION_TRANSITIONS` pattern.
      - [x] Implement `attempt-lifecycle.ts`: pure `evaluateRunReceipt` idempotency/stale-attempt decision function plus `recordAttempt`/`recordAcceptedReceipt` reducers.
      - [x] Add `FailureDetail` to `RunReceipt`, required iff `outcome === "failed"`.
      - [x] Add `attempt-lifecycle.test.ts` covering the dispatch state machine (exhaustive illegal-transition enumeration) and every `evaluateRunReceipt` branch, including the attempt-1-fails/attempt-2-dispatched/attempt-1-receipt-arrives-late race.
      - [x] Regenerate fixtures/schemas for the `RunReceipt` shape change; document the lifecycle in `packages/protocol/docs/attempt-lifecycle.md`.
