  - description: |
      ## Product Context
      User should remain inside Traycer conversation while MapCtx supplies richer planning.

      ## Expected Outcome
      A Traycer skill can attach an epic, create/enrich MapCtx tasks, claim a wave, materialize tickets, and publish receipts.

    ## Acceptance
      - [x] `mapTaskToDispatchEnvelope` maps a canonical protocol `Task` into a schema-valid
        `DispatchEnvelope`; mapping tests assert task identity, project ID, executor capabilities,
        context hash, refs, and resource claims survive without adding fields to the protocol schema.
      - [x] `renderTraycerTicket` emits only Traycer-closed frontmatter (`kind`, `title`, `status`),
        includes MapCtx task/dispatch/project/context links, and returns an explicit
        `requiresHumanTraycerAttach` boundary because Markdown cannot create a Yjs ticket or live assignment.
      - [x] `importTraycerTicket` parses a Traycer ticket into a Traycer `ExternalRef` and marks it
        `unplanned: true` with missing `domains`, `paths`, `dependencies`, and `acceptance`; test proves
        Traycer-first input cannot silently enter a runnable wave.
      - [x] `planWaveDispatch` delegates wave selection to `@mapctx/planner` and maps every planner
        wave task to one validated envelope; a synthetic two-task wave test verifies mapping without
        pinning planner edge-direction behavior.
      - [x] Skill documents MapCtx-first and Traycer-first command order, claim/receipt CLI usage,
        explicit epic/artifact links, artifact promotion boundary, and prohibition on transcript storage.
      - [x] Multi-task smoke scenario is exercised at adapter level with a synthetic wave; live Traycer
        Yjs creation, agent assignment, and Traycer-to-MapCtx sync are declared human/operator boundaries,
        not simulated as completed automation.

    ## Steps
