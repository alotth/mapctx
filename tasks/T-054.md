# T-054

  - impact: high

  - summary: Normalize runtime usage and create explainable baseline delivery estimates.
  - description: |
      ## Product Context
      Tokens, subscription limits, billed cost, elapsed time, and active agent time are different signals.

      ## Expected Outcome
      Immutable P50/P90 snapshots use real events and conservative priors instead of hidden fixed durations.

      ## Acceptance
      - [x] Accepted receipts expose lossless `UsageEvent` rows by dispatch/task, and cost events persist separately with `cashCents`, `shadowMicros`, `allocatedMicros`, billing type, status, price-table version, and applied rate.
      - [x] Duration aggregation returns session wall-clock, active time (configurable idle threshold), task interval union, and lead time; forecast input is active time.
      - [x] Forecast emits schema-valid immutable P50/P90 `EstimateSnapshot` values, using `shadowMicros` (never allocation) and explicit low-confidence conservative prior when historical samples are absent.
      - [x] Plan-period allocation is proportional to shadow cost, deterministic, and queryable; typed billing categories preserve non-token costs without conflating cash and shadow currencies.
      - [x] Store replay rebuilds usage, cost, plan-period, and estimate projections from append-only events; duplicate estimate IDs are rejected.

      ## Decisions Taken
      - [2026-08-17] `activeTime` cannot currently be measured: `RunEvent` is not persisted anywhere, and
        `RunReceipt` carries only `startedAt`/`endedAt`, so there are no interior timestamps whose gaps could be
        subtracted. The `activeTimeMs` helper is correct; nothing feeds it real data yet.
      - [2026-08-17] Rather than let the forecast silently inherit idle time while reading a field named
        `activeTime`, duration measures carry `activeTimeCoverage: measured | substituted | none`, and
        `buildEstimateSnapshot` records that coverage in `assumptions`. Coverage is weakest-link: one substituted
        sample downgrades the whole estimate, because one wall-clock stand-in is enough to make the aggregate not
        a measurement. Same principle as T-050's labeled tokenizer — the defect is the unlabeled number, not the
        imprecision.
      - [2026-08-17] `EstimateSnapshot` carries the marker through the existing `assumptions` array rather than a
        new protocol field; the typed `durationCoverage` field belongs to T-064, which owns persisting `RunEvent`
        and making `measured` reachable. Protocol left untouched here.
      - [2026-08-17] The idle threshold comparison is exclusive (`gap < threshold`), so a gap of exactly ten
        minutes counts as idle. Pinned by test so the boundary is a decision rather than an accident.

      ## Steps
      - [x] Implement event normalization and aggregation.
      - [x] Add baseline priors and immutable EstimateSnapshot.
      - [x] Label duration coverage and propagate it into the estimate snapshot.
