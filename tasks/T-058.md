  - description: |
      ## Product Context
      Planner, forecast, and UI investment is wasted if the external store or the dispatch
      contract does not survive a real round trip through Traycer across two worktrees.
      This walking skeleton isolates that risk before T-050, T-051, and T-054 spend the
      remaining ~4 weeks of the vertical slice assuming it works.

      ## Expected Outcome
      One real MapCtx task is dispatched by hand (no adapter skill, no waves, no forecast,
      no UI) through a Traycer ticket, and its receipt lands back in the shared store with
      status visible identically from two separate worktrees.

      ## Acceptance
      - [x] One real task is claimed and dispatched by hand using `DispatchEnvelope`. T-021 claimed via `mapctx task claim`; envelope hand-built with real T-021 field values, validated clean against `dispatchEnvelopeSchema` on first attempt.
      - [x] A Traycer ticket is created manually from that envelope. Hand-authored `kind: ticket` artifact — see Limitation in the writeup: this is the closest filesystem approximation possible, not the real collaborative/Yjs flow; T-053 still has to build the automation bridge.
      - [ ] `RunReceipt` returns and updates store status. **Did not pass as written.** Synthetic `RunReceipt` validated clean against `runReceiptSchema` and `evaluateRunReceipt` (accept + duplicate-reject both correct), but nothing in `@mapctx/store` persists it — approximated with `mapctx task release`, which updates claim state, not `RunReceipt.outcome`/`changedFiles`/`failure`. This is the task's main finding, tracked as T-060.
      - [x] Status and receipt are visible identically from two separate worktrees resolving the same store. Claim/release round trip proven: identical `claimId`/`leaseToken` seen from worktree B immediately after worktree A's claim; release from A immediately unblocked a claim from B.
      - [x] No waves, no forecast computation, and no UI code are added to satisfy this task.

      ## Non-Goals
      - Automated Traycer adapter skill (T-053).
      - Resource-aware wave scheduling (T-051).
      - Forecast or Gantt rendering (T-054, T-055).

      ## Steps
      - [x] Pick one real MapCtx task as the skeleton subject. T-021 — small, `backlog`, docs-only, no overlap with concurrent T-059 work.
      - [x] Dispatch it by hand against the store and protocol built in T-049/T-052.
      - [x] Open a second worktree and confirm identical claim/status. Two disposable worktrees off a local cutover commit; cleaned up after, zero impact on the real branch.
      - [x] Record gaps found in store/protocol before starting T-050, T-051, or T-054. Four gaps recorded; see Decisions Taken and [walking-skeleton writeup](/Users/alt/.traycer/epics/e8873251-f6f0-490d-be16-8e5655300237/artifacts/t058-walking-skeleton/index.md).

      ## Decisions Taken
      - [2026-08-16] Store and protocol survive a real cross-worktree claim/release round trip. T-050/T-051 can proceed on that basis.
      - [2026-08-16] Dispatch/receipt has no store-side persistence yet — `evaluateRunReceipt` is deliberately pure/stateless, and `@mapctx/store`'s event types cover project/task/claim/checkpoint only, not dispatch/run. T-054 (forecast) needs "did the last attempt complete and what changed" to durably exist before it can read it. Tracked as T-060, gating T-054.
      - [2026-08-16] No CLI path from "I have a `RunReceipt`" to a store write (`mapctx-cli.ts` wires `claim`/`renew`/`release` only, though `projections.ts` already supports `task.patched` internally). Same gap as above, one layer up — folded into T-060.
      - [2026-08-16] "Create a Traycer ticket from an envelope" has no first-class mechanism; the hand-authored artifact file is the practical ceiling without building T-053 early. Confirms T-053 is still real work, not just wiring.
      - [2026-08-16] Zero bugs found in `dispatchEnvelopeSchema`, `runReceiptSchema`, or `evaluateRunReceipt` — all validated real T-021 data and behaved as documented on the first attempt. T-052 holds up under a real round trip.
