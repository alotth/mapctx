# T-061

  - role: backend
  - impact: medium
  - estimatedEffort: 4d
  - prerequisites: [T-051, T-060]
  - blocking: []
  - filesAffected: [packages/planner, packages/store]
  - testsRequired: [collision detection tests, overbroad detection tests, ClaimViolation query tests, no-emission-before-terminal tests]
  - summary: Detect realized write collisions and lost parallelism after a wave completes, by diffing receipt changedFiles against planning-time claims.
  - description: |
      ## Product Context
      `ResourceClaim` is a prediction made before the code it describes exists, so it is wrong in both
      directions. ADR 0003 settles that claims are advisory and the worktree merge is the real backstop —
      which makes post-hoc detection the only honest feedback loop. Split out of T-051 because detection
      consumes `RunReceipt.changedFiles`, and T-058 proved receipts have no durable home until T-060 lands.

      ## Expected Outcome
      After every dispatch in a wave reaches a terminal receipt, both failure directions of a claim
      prediction are visible as queryable events a human can use to retune claim inference by hand.

      ## Acceptance
      - [x] `ClaimViolation` (schema already exists in `@mapctx/protocol`, added by T-048 — reuse it, do
            not redefine) is emitted as a derived event only once every dispatch in a wave has a terminal
            `RunReceipt`. Never in real time: the ground truth (`changedFiles`) does not exist until runs
            complete.
      - [x] `kind: "collision"`: two same-wave tasks' actual `changedFiles` intersect on a path neither
            declared claim covered, or covered too narrowly — the wave should have been serialized and
            wasn't. This is the dangerous direction.
      - [x] `kind: "overbroad"`: a claim collision serialized two tasks into different waves at planning
            time, but their actual `changedFiles` never intersected on the path that caused the split.
            Detection cross-references T-051's per-pair serialization explanation against the receipts.
      - [x] Emitted violations persist through the store's event log (T-060's dispatch/receipt
            projections are the read source) and survive across worktrees, not just in the emitting
            process.
      - [x] `ClaimViolation` events are queryable per domain/path pattern, shaped
            `(task, path, domain pattern, kind, timestamp)`.
      - [x] No ML and no automatic recalibration. `ResourceClaim.confidence` stays a static value set by
            whatever emits the claim; the stream is shaped so future automated calibration can consume it
            without a schema migration.
      - [x] A wave with incomplete or failed dispatches emits nothing rather than emitting partial
            results — tested explicitly.

      ## Decisions Taken
      - [2026-08-16] Split out of T-051 so the planner is not blocked behind receipt persistence it does
        not otherwise need. See T-051 Decisions Taken.
      - [2026-08-15] `ClaimViolation` is one entity with `kind: collision | overbroad`, derived at
        wave-completion from receipt diffing, not a real-time check. See ADR 0003 §Resource claims are
        advisory.
      - [2026-08-17] `waveId` is execution-plan context, not a durable wave entity; caller owns its
        stable UUID and supplies it with dispatch references. T-061 does not add a wave projection.

      ## Steps
      - [x] Read completed-wave receipts through T-060's projections.
      - [x] Implement `changedFiles` diffing for both violation kinds.
      - [x] Persist emitted violations as store events.
      - [x] Implement the queryable report by domain/path pattern.

      ## Implementation Notes
      - [2026-08-17] Added deterministic post-hoc detector in `@mapctx/planner` and store-side
        `recordClaimViolations`, which reads exact `(dispatchId, attempt)` receipts and appends one
        `claim-violation.detected` event per derived violation. Incomplete, missing, or non-completed
        receipts short-circuit before any append. Claim-violation projection is registered as migration
        002; v1-to-v2 upgrade preserves existing projections and event history.
