  - summary: Cost ledger exists per-run (CostEvent/PlanPeriod); add the Budget entity (plannedCents per epic/project), consumption rollup, remaining/spent%, and exploratory value_estimated/value_realized.
  - description: |
      ## Product Context
      Analysis vs OpenProject/Plane/TASKS.md (2026-09-05): MapCtx has per-run cost events but no Budget entity that actuals consume. The learning loop (actuals -> forecast) exists via EstimateSnapshot; the capital question (planned -> spent -> remaining -> still worth it?) does not. value_estimated/value_realized is unclaimed territory in AI-native tools but needs a value unit decision first.

      ## Expected Outcome
      Budget entity in protocol/store, consumption rollup per epic/project, variance report (progress vs budget consumed), and a documented decision on the value unit before value_* fields are implemented.

      ## Refinements (user, 2026-09-05)
      - **Subscription agents (value_realized path)**: users hold fixed-price plans per agent (Codex, Claude Code). Two value sources, both already designed in ADR 0003's cost model: (a) **manual plan entry** -- the user records the plan payment (amount + date), which feeds `PlanPeriod` (entity exists since T-054); subscription runs carry `cashCost 0`, `shadowCost` always computed from tokens x vendored price table, and `allocatedCost` = the plan fee rated proportionally to shadowCost. (b) **token-counted value** like Traycer's aggregate metering -- UsageEvent already captures tokens per run; shadowCost is the model-aware normalization. So value_realized for subscription agents is the allocatedCost aggregation, not new plumbing.
      - **Budget unit is time, not only money**: the same Budget entity should accept a time budget (planned hours/minutes per epic) consumed by measured activeTime -- the dual of the money budget. Unit-agnostic budget (money | time), same consumption/rollup/variance machinery.
      - **Defer value_estimated/value_realized**: noted, not implemented. Blocked on the value-unit decision below.

      ## Decisions Taken (user, 2026-09-05)
      - **Money representation: crypto-style value pattern.** Integer minor units + `decimals` + currency code
        (e.g. `{ amountMinor: 200000000, currency: "USD", decimals: 6 }` -> "200.000000 USD"). Adapts to any
        currency without float. USD is the working default for amounts (plans, provider pricing, budgets);
        other currencies are stored natively when they appear. Cross-currency rollup is a rare, manual,
        explicit case: when it happens, the conversion rate + date is recorded as data at that moment -- no
        FX service, no automatic conversion, no silent normalization.
      - **Budget lives in the store** via `mapctx budget set` (event log), with generated projection on the
        epic detail. Revisions/top-ups come from history for free.
      - **value_estimated/value_realized deferred to a dedicated RFC.** T-070 ships Budget (money | time)
        with consumption/rollup/variance only.
      - **Account abstraction owns the plan, projects consume it.** The plan payment ("paguei $200 no Codex
        em 05/09") is recorded on an Account ("Codex Pro"), not on a project: `Account -> PlanPeriod ->
        allocatedCost rateado por shadowCost entre os runs dos projetos ligados àquela conta no período`.
        This demotes T-054's project-scoped PlanPeriod to a consequence: migration (004) re-scope
        PlanPeriod.accountId, and each project binds which accounts it draws from.

      ## Open Decisions for Execution
      - Account model: are accounts global (shared across every project on the machine) or per-portfolio?
        Default proposal: global in ~/.mapctx (like the project store), since solo users pay once per plan.
      - FX snapshot source: manual entry first (user types the rate used), provider lookup later.
      - Budget unit grammar: `money|time` on one entity vs two entities (BudgetMoney, BudgetTime).
