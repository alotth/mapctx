  - summary: Difficulty discovered mid-flight (Easy -> Hard) must re-attribute the actual to the correct pool AND leave behind the planned-vs-discovered delta as the estimation-quality metric.
  - description: |
      ## Product Context
      Users re-classify tasks mid-flight when discovered difficulty exceeds the initial guess. Pool attribution already reads the current workload value, so re-attribution works -- but the (planned, discovered) pair is lost. That delta is the calibration signal for up-front estimation quality, which is what improves future planning, not just current pooling.

      ## Expected Outcome
      - Dispatch/receipt or sample records workloadAtClaim (planned) and workloadAtReceipt (discovered).
      - Pools keyed by discovered workload (already true via current-record reads; make it explicit and test-pinned).
      - EstimateSnapshot assumptions carry the delta when planned != discovered; aggregation exposes estimation-error per original workload (e.g. 'Easy guesses ran Hard 60% of the time, x9 over').
      - Skill instructs agents to re-classify on discovery (task update --set workload=...) instead of letting a long actual pollute the planned pool.

      ## Open Decisions for Execution
      - Where the planned value is captured: claim-time snapshot on the dispatch envelope vs first receipt read.
      - Whether repeated re-classifications are kept as history or last-wins.
