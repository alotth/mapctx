      ## Problem
      The unanchored in-row forecast bar renders a duration-scaled width across the calendar lane, so a 14m P90 reads as a multi-month calendar span (user screenshot). Even the anchored forecast bar invites misreading. User decision: bars are for planned and executed only; forecast is text.

      ## Decisions taken
      - Remove forecast bars from the calendar lane entirely: no .calendar-unanchored-forecast, and no positioned .calendar-span-bar.forecast / .forecast-p50 either.
      - Forecast always renders as a compact text chip in the label column task-signals row: "P50 14m / P90 1h" (formatDurationMs), alongside existing provenance/variance chips. For tasks without forecast keep current "no forecast" chip behavior (epics).
      - Planned bar keeps inclusive width; actual keeps exact width; today/grid/aria unchanged except: row aria/tooltip must no longer claim a forecast bar position; for anchored tasks, planned bar tooltip may append "forecast P50 x ending <ISO>" — no new bar.
      - Files: packages/vscode-extension/src/html/workspaceV2.js/.css only.
