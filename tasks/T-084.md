  - summary: Expose budget, consumed cost, remaining amount, spent percentage, and task-level cost breakdown in Workspace V2.
  - description: |
      ## Product Context

      `T-070` supplies the store-side Budget and cost rollups, but Workspace V2 has no dedicated financial surface. The
      current execution view exposes only tracked run cost; it does not answer planned budget, spent, remaining, or cost
      versus delivery progress.

      ## User Story

      As a project operator, I want to inspect financial consumption by project/epic and task so I can see whether delivery
      is within budget and which work is consuming it.

      ## Expected Outcome

      Workspace V2 exposes a compact Cost view backed by `T-070` projections:

      - summary cards for planned budget, consumed, remaining, and spent percentage;
      - money/time unit and currency shown explicitly;
      - breakdown by epic and task, with task detail opening preserved;
      - progress-versus-budget signal where both measures exist;
      - truthful empty states for no budget, no cost data, and mixed/unsupported currency;
      - no fabricated zeroes and no client-side cost recomputation.

      ## Product/UI Decisions

      - Start with a dedicated Cost section/tab in Workspace V2, reusing the existing visual language and task filters.
      - Use summary cards above a sortable table/tree: Epic, task, planned, consumed, remaining, spent%, coverage.
      - Default sort: highest spent percentage, then consumed amount; allow sorting by name, planned, consumed, remaining,
        and progress variance. Persist no new complex user preference unless needed by the existing view state pattern.
      - Keep cash, shadow, and allocated cost distinguishable; never collapse them into one unlabeled number.
      - Scope is read-only visualization. Budget/account mutations remain CLI/store responsibilities.

      ## Out of Scope

      - Editing budgets, accounts, plan periods, or FX rates in the UI.
      - Subjective business-value fields (`value_estimated`/`value_realized`).
      - Gantt dependency connectors; Gantt continuity is handled separately through ordering/grouping first.

      ## Suggested First Vertical Slice

      Expose one read-only project/epic budget-status payload from the existing workspace host, render summary cards and one
      sortable task table, then add richer cost attribution only after the empty and partial-data states are verified.
