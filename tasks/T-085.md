  - summary: Add persisted Start/End/Epic/Wave/Status/ID sorting while preserving Epic/Wave grouping and explicit unscheduled rows.
  - description: |
      ## Product Context

      Workspace V2 already groups roadmap rows by Epic or Wave, but row order is fixed to execution wave, status, and ID.
      Users cannot choose a visual ordering that makes schedule continuity legible when dates exist, and there is no need to
      introduce dependency lines before ordering proves insufficient.

      ## User Story

      As a project operator, I want to sort the Gantt/roadmap by schedule or hierarchy so I can follow continuity across
      Epics and tasks without fabricated dependency geometry.

      ## Expected Outcome

      Roadmap exposes a sort selector with Start, End, Epic, Wave, Status, and ID. Selected order applies inside the current
      Epic/Wave grouping, keeps groups intact, places undated tasks last for date sorts, and remains stable across renders.

      ## Product/UI Decisions

      - Keep existing Epic/Wave grouping, timeline scale, collapse state, and task detail interactions.
      - Date sort uses planned dates first, then measured actual timestamps when planned dates are absent.
      - Missing dates sort after dated rows; date ties use parent ID, then task ID.
      - Hierarchy/group sorts keep current group order and sort rows by the selected hierarchy key, then parent ID, then task ID.
      - Persist selected sort locally using the existing roadmap preference pattern.
      - Dependency connectors/arrows are explicitly out of scope for this slice; revisit only if ordering/grouping fails to tell
        the delivery story.

      ## Suggested First Vertical Slice

      Add persisted selector and deterministic comparator in Workspace V2, verify each mode against a fixture containing nested
      Epics, dated/undated tasks, equal dates, and actual-only timestamps.

      ## Outcome (2026-09-11)

      Implemented in `workspaceV2.js`/`.css`: persisted sort selector, Start/End/Epic/Wave/Status/ID comparators, planned-date
      sorting with actual-timestamp fallback, missing-date-last behavior, parent/ID tie-breakers, and existing Epic/Wave
      group preservation. Dependency connectors remain out of scope.

      Verification: node syntax check, ESLint (0 errors; existing curly warnings), `git diff --check`, typecheck, lint, and an
      isolated six-mode comparator check all passed. Browser review against the built Workspace V2 also found and corrected
      the empty `data-roadmap-sort` attribute check; after rebuilding, persisted selection, all six modes, preserved
      Epic/Wave grouping, expected horizontal timeline overflow, and zero console errors were verified.
