  - summary: Expose archived as a terminal planning status and filterable task state; preserve paused as resumable and done as completed.
  - description: |
      Add first-class planning status `archived` for work that will not be done. It is terminal like `done`: reject further planning moves, claims, and dispatches; release active claims; distinguish it from `paused`, which remains resumable, and `done`, which records completed work. Carry status through protocol, store/export and reconciliation, CLI, parser and task views. Archived tasks stay in project history, are hidden from the default project view, and remain available through status filters. Do not auto-migrate existing paused tasks; migration requires explicit operator choice.

      ## Acceptance
      - [ ] `archived` is a supported canonical planning status and exports/reconciles without drift.
      - [ ] Tasks can transition into `archived` from eligible nonterminal states; archived tasks cannot transition or be dispatched/claimed afterward.
      - [ ] `paused` remains resumable with existing behavior; `done` continues to mean completed.
      - [ ] CLI, parser, and relevant task views recognize and render `archived` distinctly from `done` and `paused`.
      - [ ] The default project view hides archived tasks; selecting the archived status filter reveals them.
      - [ ] Documentation and status mappings describe archived semantics; existing paused tasks remain untouched.
