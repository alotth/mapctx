  - summary: Make the workspaceV2 kanban read task/board data from the SQLite store through the mapctx CLI (same path as /api/gantt) instead of parsing TASKS.md, so the UI reflects store authority
  - description: |
      The workspace server (packages/sync-engine/src/workspace-server.ts) injects a TASKS.md-parsed bootstrap into workspaceV2 and serves task detail from markdown files. With plansAuthority=store the board UI can diverge from the store. Migrate the kanban data path to the store via the CLI, mirroring how /api/gantt uses mapctx gantt --json (readStore path when plansAuthority=store, TASKS.md fallback pre-cutover). Keep the pre-cutover behavior working for file-authority repos.       Update the OpenCode plugin dashboard only if it shares the workspace server data path; VS Code webviews that parse the open document stay out of scope.

      ## Acceptance
      - [x] With `plansAuthority = "store"`, the workspaceV2 board bootstrap and kanban refresh endpoints serve tasks from the SQLite store via `mapctx` CLI, not from TASKS.md parsing.
      - [x] Pre-cutover repos (`plansAuthority` not `store`) keep the existing TASKS.md-parsed behavior unchanged.
      - [x] Kanban card fields and columns render identically to the current UI for the same underlying data (no regression in badges, a11y, density from T-080).
      - [x] Tests cover both store-authority and pre-cutover data paths for the migrated endpoints.
