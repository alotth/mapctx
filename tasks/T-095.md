  - description: |
      Two user-facing launch defects: (1) bare 'mapctx' only prints help instead of opening the workspace UI. (2) The workspace lands on registry.activeTargetId even when that target's TASKS.md is gone (e.g. project:precut -> /tmp/precut deleted), so every page request 500s ('Target TASKS.md not found') and the UI never shows the real projects under ~/repos. Fix in mapctx-cli.ts launch policy (workspace-server.ts stays frozen): empty command launches the UI; before starting, if the active target's TASKS.md is missing, repoint activeTargetId at the first registry project whose TASKS.md exists and persist; if the port already serves the workspace UI, print the URL, open the browser, and exit instead of EADDRINUSE.
