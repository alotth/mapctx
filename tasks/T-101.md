  - description: |
      ## Product Context

      History of the 50 done tasks is not recoverable from the board: `completedOn` is bulk-stamped 2026-05-29 (migration date), only 9 have receipts and only 5 have commits naming the task. The real record is in local agent sessions. Probed 2026-09-30: Codex `~/.codex/sessions/**/*.jsonl` (65 mapctx sessions, 2026-04-24 onward, per-event timestamps), OpenCode `~/.local/share/opencode/opencode.db` (67 mapctx sessions, 4244 messages, 2026-03-05 onward, tables session/message/part, ms timestamps), plus Claude Code transcripts (few left). Every done task is mentioned in both Codex and OpenCode, but a bare `T-###` mention is noise (a session that lists TASKS.md names every task; 91 cited IDs are not on the board), so linking must weigh signals.

      ## Model

      - Harness adapters (claude-code, codex, opencode) emit the same timestamped, owner-tagged events; T-100's interval extractor is reused. Only timestamps, owners, ids, hashes are kept, never conversation content.
      - Task linking by signal strength: (1) `mapctx task claim|dispatch|move <T-###>` tool calls; (2) edits to `tasks/<T-###>.md` or files in the task's `filesAffected`; (3) branch/worktree name or first-prompt ID; (4) bare mention = weak hint only. A session can link to several tasks (time split by signal); ambiguous links go to manual review in the dry-run.
      - Evidence tiers: measured (session intervals), inferred (commits/files/window), declared (start/due dates), no-history. Backfill is written as retroactive attestation via the existing claim/dispatch/receipt path with true historical `startedAt`/`endedAt`; nothing fabricated. Inferred and declared tiers never enter estimate-accuracy or calibration statistics.
