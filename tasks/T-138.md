  - description: |
      ## Product Context

      Roadmap M1 (artifact `roadmap-local-to-github`) e ADR 0005 (opção B com provider local). Hoje a única recuperação da store é `mapctx store init`, que reconstrói a partir do checkpoint `TASKS.md`/`tasks/*.md` — e o achado da T-128 mostrou que `recoverStoreFromCheckpoint` lê esse arquivo do DISCO, não do Git. O histórico de eventos, claims, receipts e custo mais antigo que o checkpoint se perde. Antes de desligar os snapshots no Git (A0) e antes de qualquer migração para o GitHub, a store precisa de backup e restore próprios.

      ## Scope

      - `mapctx store backup [--out <dir>] [--json]`: cópia consistente da store do projeto (db com checkpoint WAL ou `VACUUM INTO`, journal `events/`, attestations, meta) num arquivo/diretório datado, com manifesto (versão do schema, contagem de eventos, sha256 por arquivo). Default fora do repo (`~/.mapctx/backups/<projectId>/`).
      - `mapctx store restore <backup> [--json]`: valida o manifesto e restaura numa store vazia ou após confirmação explícita; recusa backup de schema mais novo que o binário; roda a verificação do journal depois.
      - Snapshot automático antes de migrações de schema (runner de `db.ts`) e antes de `store repair`, com retenção simples (últimos N).
      - `recoverStoreFromCheckpoint` passa a poder ler o checkpoint do Git (`git show <ref>:TASKS.md`) quando pedido, e a documentação diz qual fonte foi usada.
      - Ajuda, README e CHANGELOG 0.4.0.
      - Fora do escopo: backup remoto/nuvem, criptografia.
